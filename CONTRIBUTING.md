## Quick Start

1. **Read our vision**: [README.md](README.md) — understand what PoPB is and why it matters
2. **Join the community**: [Discord](https://discord.gg/zwiserfit) — ask questions, share ideas, meet other builders
3. **Find your first contribution**: Browse [Good First Issues](https://github.com/ZWISERFIT/zwiserfit-ai-store-manager/issues?q=is%3Aissue+is%3Aopen+label%3A%22good+first+issue%22)

## Contributor Tier System

We recognize contribution at four levels. Progression is organic — no application needed.

| Tier | Name | Criteria | Benefits |
|:----:|:-----|:---------|:---------|
| **L1** | Contributor | 1 merged PR or 3+ quality issue comments | Listed in CONTRIBUTORS.md |
| **L2** | Active Contributor | 3+ merged PRs or 1 led RFC discussion | Invite to private `#🏗️-contributors` Discord channel |
| **L3** | Maintainer | 6+ months sustained contributions + core team invite | Issue/PR label management, technical decision input |
| **L4** | Core Member | Architecture-level contribution + team vote | Repo settings access, ZWISERFIT Team page listing |

All tiers are tracked in [CONTRIBUTORS.md](CONTRIBUTORS.md), automatically updated on each merge.

## How to Contribute

### 🐛 Report a Bug

Open an [Issue](https://github.com/ZWISERFIT/zwiserfit-ai-store-manager/issues/new) with:
- Clear title and description
- Steps to reproduce (if applicable)
- Environment details (OS, browser, SDK version)

Labels: `bug`, `P0`/`P1`/`P2`

### 💡 Suggest a Feature

Start a [Discussion](https://github.com/ZWISERFIT/zwiserfit-ai-store-manager/discussions) in the Ideas category. For major features, consider writing a short RFC first.

Labels: `enhancement`, `RFC`

### 📝 Improve Documentation

Documentation contributions are highly valued. Submit PRs against the `/docs` directory.

Labels: `docs`

### 🔧 Submit Code

1. **Find an issue** to work on — comment `/claim` to self-assign
2. **Fork** the repository
3. **Create a branch**: `feature/short-description` or `fix/short-description`
4. **Write code** following our style guidelines
5. **Add tests** where applicable
6. **Submit a PR** referencing the original issue

## Pull Request Guidelines

### Before Submitting

- [ ] PR references an existing issue (create one first if none exists)
- [ ] Code follows existing style patterns
- [ ] Tests pass (CI will verify)
- [ ] Documentation updated if API/behavior changed
- [ ] Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/)

### Review Process

1. A maintainer will acknowledge your PR within **24 hours**
2. Automated checks run (lint, test, security scan)
3. At least one maintainer review required
4. All conversations resolved before merge
5. Squash merge preferred

### Response Time Commitment

| Stage | Target | Escalation |
|:------|:------|:-----------|
| First response to PR | ≤24h | Ping in Discord `#🏗️-pr-review` |
| Review turnaround | ≤72h | Ask in `#🏗️-builders` |
| Issue first reply | ≤4h (business hours) | Ping @Luna in Discord |

## Code of Conduct

We are committed to fostering an open and welcoming environment.

**Expected:**
- Respectful and constructive communication
- Focus on technical merit, not identity
- Assume good faith
- Help others grow

**Unacceptable:**
- Harassment, discrimination, or personal attacks
- Spam, trolling, or intentionally disruptive behavior
- Publishing private information without consent

Reports: Discord DM to @Luna or email [conduct@zwiserfit.io](mailto:conduct@zwiserfit.io)
